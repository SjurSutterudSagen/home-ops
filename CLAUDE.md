This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

A GitOps-managed Kubernetes home cluster running on **Talos Linux**, with **Flux** for continuous reconciliation and **Cilium** as the CNI. All workloads are defined as Flux `Kustomization` + `HelmRelease` objects under `kubernetes/`. Secrets are encrypted with SOPS+AGE and stored in Git.

The `kubernetes/`, `bootstrap/`, and `talos/` directories are **generated** — edit their corresponding Jinja2 templates in `templates/` and re-run `task configure`.

## Key Commands

All commands use [Task](https://taskfile.dev/). Tools are managed by [mise](https://mise.jdx.dev/).

```sh
mise trust && mise install   # Install all CLI tools first (kubectl, flux, talosctl, helm, sops, etc.)

task configure               # Validate schemas (CUE), render templates (makejinja), encrypt SOPS secrets
task reconcile               # Force Flux to resync from Git
task template:debug          # Show cluster state: certs, pods, HelmReleases across namespaces

# Talos operations
task talos:generate-config             # Re-render talhelper configs
task talos:apply-node IP=192.168.50.x  # Apply Talos config to a node
task talos:upgrade-node IP=192.168.50.x
task talos:upgrade-k8s

# Bootstrapping (first-time only)
task bootstrap:talos         # Generate Talos secrets, apply to nodes, bootstrap etcd
task bootstrap:apps          # Install cilium → coredns → cert-manager → flux via helmfile

task                         # List all available tasks
```

## Architecture

### Template Rendering
`cluster.yaml` and `nodes.yaml` are the source of truth for cluster-wide and per-node configuration. `task configure` uses [makejinja](https://github.com/mirkolenz/makejinja) to render all `templates/config/**/*.j2` Jinja2 templates into `bootstrap/`, `kubernetes/`, and `talos/`. **Never edit generated files directly.**

Jinja2 delimiters are `#{...}#` for variables and `#%...%#` for blocks (to avoid conflicts with YAML `{}` syntax). Custom filters/functions live in `templates/scripts/plugin.py`.

### Secrets
SOPS+AGE encrypts all `*.sops.*` files. The AGE private key is in `age.key` (referenced via `SOPS_AGE_KEY_FILE`). Encryption rules are in `.sops.yaml` (generated by `task configure`). To edit an encrypted file: `sops <file>`.

### GitOps Flow
Flux watches this repo and reconciles `kubernetes/` on every commit. The root entry point is `kubernetes/flux/cluster/`. Apps are organized under `kubernetes/apps/<namespace>/`. Each app typically has a `Kustomization` pointing to a directory containing a `HelmRelease`.

### Bootstrap Order
1. CRDs (envoy-gateway, cloudflare-dns, kube-prometheus-stack)
2. `cilium` → `coredns` → `spegel` → `cert-manager` → `flux-operator` → `flux-instance`
3. Flux reconciles everything else from Git

### Networking
- **Cilium** in kube-proxy-replacement + DSR load balancer mode
- **Envoy Gateway** with two gateways: `envoy-internal` (`192.168.50.232`) and `envoy-external` (`192.168.50.233`, via Cloudflare Tunnel)
- **cloudflared** for external ingress; **k8s_gateway** for internal split-horizon DNS at `192.168.50.231`
- **external-dns** manages Cloudflare DNS records automatically

## CI

- **`flux-local.yaml`** — runs on PRs touching `kubernetes/**`: validates HelmReleases and Kustomizations with `flux-local test`, posts rendered diffs as PR comments.
- **`e2e.yaml`** — full template smoke test (only runs on the upstream template repo).

## Renovate

Dependency updates are automated via Renovate (`.renovaterc.json5`). It covers Helm charts, container images, GitHub Actions, GitHub releases, and mise tools. Auto-merges minor/patch GitHub Actions updates; runs on weekends for other updates.
